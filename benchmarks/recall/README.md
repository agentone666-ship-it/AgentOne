# AgentOne Recall Benchmark v1

目标：用户只说“今天早上在工位和某某聊的那件事，找出录音帮我落地”，宿主能找到候选，检查原话和前后文，形成可追溯的事项交接。

## 本轮测量边界

- 258 条录音索引（18 条目标/混淆素材 + 240 条干扰），18 个固定场景：12 开发场景、6 迁移场景。另有 4 条探索性语言挑战。
- 全部是作者编写的合成转写、标签、事项元数据与事件。音频文件是显式标记的检索载荷，**不是语音，也不测 ASR 或音质**。
- 请求通过真实 MCP 子进程；生产检索代码不读取场景 ID 或正确答案。基线在改动前先提交；后续更强基线和候选使用同一关键词/时间解释器。
- 迁移集仍由同一作者编写、实现者可见，并非独立盲测。18/18 仅表示这些固定场景通过，不能当真实用户准确率。
- 事项原话/状态是人工 fixture，本轮不测 LLM 从语音推断任务的正确率，也没有真实发消息、改业务系统或执行用户任务。

## 本机结果

| 指标 | 原工具：整句直接搜 | 原工具：先拆关键词/时间 | 新候选与上下文接口 |
|---|---:|---:|---:|
| 有来源场景 Top-1 | 0/15 | 12/15 | 15/15 |
| 全场景通过 | 2/18 | 8/18 | 18/18 |
| 事件关联 | 0/2 | 0/2 | 2/2 |
| 事项交接状态与原话检查 | 0/3 | 0/3 | 3/3 |

原工具“整句直接搜”是下限；先拆关键词/时间才是更有意义的检索基线。基线未实现新的上下文交接接口，因此状态/交接差异反映工具能力，不能解读为优于一个有充分工具编排的宿主 Agent。

原始逐例结果：[baseline.json](baseline.json)、[structured-baseline.json](structured-baseline.json)、[candidate.json](candidate.json)。延迟包括本机 MCP 调用与相关证据读取，不含 ASR、LLM 或实际执行；样本很小，不作线上 SLA。

探索性语言挑战仅 **2/4** 通过，见 [challenge.json](challenge.json)。当前已补“今早”等日期归一化，以及词典未收录中文词组的保留；语义改述与混合网页/谈话线索仍可能漏召回。`query_expansions` 支持宿主推理后的短查询变体；测试证明“断网还能用”给出“离线缓存”变体后能找到证据，但**不证明宿主自己能正确生成该变体**。

## 固定场景

时间/地点/人物与主题、同人不同事、双轨重复、地点缺失、时间记错、同日不同时间、跨月、缺转写、多个候选需追问、没有来源需拒答、隐藏/删除、网页作上下文线索、取消后不能继续执行、建议不能当承诺、录音提示注入、时区。

额外回归覆盖：DST 边界，整天同一采集 session 不能跨无关片段合并成一次谈话，事件哈希/分页/隐藏，陈旧音频和伪造原话不能作为交接证据。

## 运行

```bash
node benchmarks/recall/run.mjs --baseline
node benchmarks/recall/run.mjs --structured-baseline
node benchmarks/recall/run.mjs --check --output build/recall-candidate.json
node benchmarks/recall/run.mjs --challenge
```

CI 在 Node 22.19/24 上执行固定 18 例门禁并上传 JSON；挑战集单独报告，不包装成全绿。

## 下一轮真实效果验收

1. 本机 ASR 确认可用，录制有明确同意的中文短对话；人工标记原话、时间、候选与允许执行的事项。
2. 接入用户实际选择的 MCP 宿主，记录真实工具轨迹和模型输出，测查询扩展、正确候选、追问质量、原话支持率、取消/提议理解及完成回执。
3. 另设未参与开发的录音和改述测试集，测 ASR 错字、人物同音、地点缺失、跨月和多段记忆。真实行动只在专用测试目标中执行并核验，不以草稿冒充完成。

## 独立设备烟测

本机同步 19,410 条旧事件并经 UI/Swift→Node 内容哈希读取核对；一次真实库合成无关词检索返回 0 候选，约 1.9 秒。已有实际 on-device 非空转写及其原话→搜索→原音哈希回读。该检查未输出私人原话，没有人工逐字标注，既不是 ASR 准确率，也不是用户模糊回忆的命中率；不合并到上述合成数据分数。
