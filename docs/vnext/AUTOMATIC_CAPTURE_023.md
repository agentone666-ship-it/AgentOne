# 自动记录与声音活动（0.2.3）

## STATUS

用户要求不用记得每天手动开启。现已安装 0.2.3，按本次请求恢复本机自动记录，并保持运行。

- 默认自动记录，首次请求一次系统授权；授权完成后自动开始，后续启动不重复弹窗。
- 默认注册登录启动，是否允许以系统实际状态为准；界面显示注册状态并提供系统设置入口。
- 恢复设备唤醒/解锁前的录制意图；休眠始终暂停，锁屏暂停偏好保留。
- 手动暂停是持久意图，重启不会取消。本机已有的暂停状态在本次明确要求下恢复，没有将旧暂停默认忽略。

## DECISIONS / CHANGES

1. 为避免错过开头和微弱声音，授权后连续保存；声音活动检测只添加线索，不按音量裁掉静音。不是只有“听见声音之后才开始监听”。
2. 系统音使用 ScreenCaptureKit；本机验证发现 SCStream 麦克风一路没有回调，改为独立 AVAudioEngine 麦克风输入。两路共用会话与 wall/host-clock 锚点，用 AVAudioTime.hostTime 对齐。
3. CoreAudio tap 在非 UI 线程构建，复制可复用缓冲后交给串行写入队列；避免 Swift 6 MainActor 断言，停止时移除 tap，旧回调不能重新打开文件。
4. UI 分别显示等待输入 / 安静且持续保存 / 检测到声音。仅音量观测，不冒充人声、人物或语义识别。
5. 每段 context_json 保留 audio_activity：RMS 阈值、观测窗口数、活跃窗口数、峰值和 sound/quiet/unknown；原有上下文不丢失，元数据明确 silence_discarded=false、semantic_classification=false。
6. PCM 检测支持 Float32 / Float64 / Int16 / Int32，支持交错和分离通道，非有限采样不生成虚假音量结论。
7. 原音访问、本机 ASR 与宿主分析仍遵循各自已有偏好；自动记录不自动开启云端分析或授权额外宿主。

## TESTS

- 完整 Swift 108 项通过；新增自动启动/暂停/首次授权策略，8 种 PCM 格式组合，静音与分路活动过期，真实编码保留安静头尾和上下文元数据，以及 CoreAudio 回调在后台执行且复制缓冲的回归。
- 音频 Harness → 真实 AAC → SQLite → MCP 子进程集成通过；最终 ZIP 签名、资源、自检、版本与真实 MCP 子进程通过。
- 设备实测：最终采集会话两路均生成录音文件并增长；正常退出后麦克风与系统音均有已封口的约 60 秒片段，SHA256 校验正确，afinfo 可读取。音量活动元数据同时出现 sound / quiet，安静片段没有被删除。
- 正常退出后重新打开实际安装 App，没有点击录音按钮，AX 直接显示“自动记录中”；新会话再次有两路输入。保持最终 App 继续记录。
- 没有收听、转写或上传本轮真实原音；没有将用户录音或内容提交到 Git。

本轮短时验证不证明全天连续性、真实重启登录、设备热切换、实际休眠恢复或 ASR/模型质量。云端状态以 PR #2 最新 Checks 为准。

## HANDOFF

- 日常不用每天点击开始。打开 App 后按保留的自动录制意图工作；登录启动是否批准可在设置页核对。
- 点击“暂停记录”后会保持暂停，需明确恢复。关闭“自动记录声音”也会停止。
- 启动失败显示原因；不会用假录音或空转写伪装成功。权限拒绝后不反复弹窗，需完成系统授权并恢复。
