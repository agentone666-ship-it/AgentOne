# AgentOne vNext：灵动岛与个人经历记忆插件

状态：产品与架构目标，2026-10-25。已开始实现双路音频＋通用 MCP；完成项与待验收项以 [实现状态](STATUS_CAPTURE_MEMORY.md) 为准。

## 1. 用户给出的方向

- 日常自动记录电脑设备的声音，保留完整录音，后台静默分析各时段并标注。
- 保留能帮助未来理解的信息，如时间、地点，以及现有 AgentOne Context。
- 近期能按“今天早上、工位、某个人、聊了某件事”查找，整理待办并交给 Agent 继续处理。
- 时间久了仍可凭模糊线索找回经历，不能只依赖用户记得日期和地点。
- 主入口改成灵动岛；AgentOne 作为现有 Agent 的插件，不再单独建设 Agent Runtime。

用户已确认：系统声音＋麦克风分别保存并对齐时间；先做通用 MCP，不绑定具体宿主 Agent。

## 2. 产品定位与结果

AgentOne 为用户的 Agent 提供可追溯的个人经历。它负责把经历记下来、索引好、找回来，
宿主 Agent 负责结合用户当前意图理解、规划和行动。

这次不是在旧应用里加一个录音按钮。默认产品将收敛为：

1. 本机采集服务：系统权限、声音和已有桌面 Context、分段、可靠保存。
2. 灵动岛：采集状态、暂停、临时排除、回忆入口和跳转证据。
3. Memory 服务：转写、事件、索引、版本与引用、删除和修正。
4. Agent 插件：检索 / 取证工具、静默分析任务接口、宿主接入说明。

不再拥有自己的聊天人格、Agent 工具循环、任务规划器和独立模型账号体系。
本机仍需运行有系统权限的轻量进程；MCP 插件本身不能取代 macOS 录音权限和生命周期管理。

## 3. 两个主要场景

### 近期：说得出场景，找回承诺

用户：“今天早上我在工位和小王聊了改版，查一下有哪些事需要我做，然后帮我处理。”

1. 根据本次查询的时区解释“今天早上”，检索同时段录音和桌面 Context。
2. “工位”和“小王”作为线索：已核实的标注可以精确过滤，用户模糊回忆默认作为排序信号。
3. 提供候选对话与原音时间位置；分清讨论建议、明确承诺、已取消事项和已完成事项。
4. 生成任务草稿，保留负责人、截止时间、依赖项和每一项的原话引用；缺失值明确为空。
5. 宿主 Agent 根据用户当前授权执行，结果回写到任务的执行记录中，附实际产物或回执。

“录音里有人说发出去”本身不是当前用户对 Agent 的发送授权。
历史录音、转写、网页和模型标签都作为资料，不能自带指令权限。

### 长期：记不清场景，仍可找到事件链

用户：“之前好像聊过某个改版为什么没做，最后怎么决定的？”

1. 从主题、同义词、人物 / 项目关系和已知方案变更检索，时间地点都可以不填。
2. 分别检索原始转写与派生记忆，不能只搜日 / 周 / 月总结。
3. 将相关讨论、决定、撤销或后续实际动作串成时间线。
4. 回答当时的决定、后来发生的变化，并给出各自的音频或桌面证据。
5. 候选不唯一时展示差异；没有证据时说无法确认，不编造人物、地点或动机。

## 4. 保存哪些信息

| 信息 | 保存内容 | 取得方式与限制 |
| --- | --- | --- |
| 时间 | UTC 开始 / 结束、当时 IANA 时区、采样时间、设备单调时钟锚点 | 系统观测；跨时区、夏令时、手动校时不能重写历史时间 |
| 音频来源 | 系统音 / 麦克风、输入输出设备、轨道、采样率、编码、声道 | 来源切换单独记录；没有独立应用轨道时不宣称知道是谁播放的 |
| 原始内容 | 可回放音频、完整转写、词句偏移、语种、重叠与听不清区间 | 保留重新转写能力；识别失败不能写成“没有说话” |
| 对话结构 | 发言轮次、局部说话人 ID、疑似人数、对话边界 | 声源与说话人不同；系统音也可能包含多人，麦克风也可能收进扬声器回声 |
| 身份 | 已确认姓名、候选身份、别名、关联证据 | 默认 speaker_1 等局部 ID；提到一个名字不等于该名字就是说话者；第一版不默认建声纹库 |
| 地点 | 用户地点标签、坐标 / 精度（如另行授权）、地点有效时间和来源 | “工位”可来自用户标注；不能由 IP、网络名或应用标题精确推断工位；无来源记 unknown |
| 同时发生的事 | 前台应用、窗口 / 文档 / URL、已有 Activity Session ID | 带采样时间和覆盖区间；前台应用不是录音内容来源的证明 |
| 关联上下文 | 用户当前任务、授权关联的日程 / 会议、项目与文件引用 | 日历参与者只是计划参加者，不能据此确认都实际发言 |
| 理解结果 | 主题、实体、决定、承诺、问题、待办候选、状态变更 | 每项都带证据片段、提取版本、支持 / 反对证据和确定程度 |
| 质量与缺口 | 静音、掉帧、睡眠、权限丢失、断流、时钟变化、回声 / 噪音 | 空白不是“这段时间什么都没发生”；不把不可录到的数据补造出来 |
| 溯源 | 事件 ID、文件内容哈希、音频区间、转写版本、模型 / 提示词版本、修正来源 | 重新分析追加版本；保留观测、用户陈述和模型推断的区别 |
| 访问与保留 | 本地 / 云端分析许可、保留策略、隐藏 / 删除记录、导出记录 | 不用重要性评分私自丢弃原始录音 |

情绪、态度、性格、关系亲疏等不作为第一版必存的“事实”。确有用途时只能是可撤销推断。
模型自报 confidence 不视为经过校准的正确概率。

## 5. 全量保留与分段

- 物理文件按 30–120 秒的可配置时间片分段；初版候选值 60 秒，便于恢复与并行处理。
- 语义对话跨越多个文件，单独维护 episode，不能把每分钟强行认作一段完整对话。
- VAD、静音检测与内容分类用于安排分析优先级和标注，默认不删除原始声音。
- 系统音与麦克风保留独立轨道及时间锚点，派生对齐视图；不得靠文件序号假设绝对同步。
- 每个日目录有覆盖清单：已录 / 暂停 / 睡眠 / 权限不足 / 设备断开 / 空间不足。
- 文件写入先落临时状态，封口 / 原子提交后才能领取分析任务；崩溃后的尾段标为不完整并尝试恢复。
- 暂停、锁屏、睡眠、重启、设备切换、屏幕热插拔、时钟变化都必须有明确状态转换。
- 自动续录需用户启用并授予系统权限；仅打开插件不能默认为开始录音。

保留策略推荐“持续保留原始内容，容量不足前提示并暂停”，由用户另外选择清理 / 导出策略。
不能一边声称“全录全保留”，一边按价值评分或录音年龄静默丢掉内容。

容量需在界面上可见。以两路合计固定 128 kbit/s 为算例：
`128000 × 86400 ÷ 8 ≈ 1.38 GB/天`，90 天约 124 GB（十进制，未计索引 / 转写 / 文件开销）。
这只是比特率估算，不是实测；无损保留、真实编码效果、能耗和模型成本必须另行测量。
“完整时间覆盖”和“无损音质”是两个不同设置，不把有损压缩描述成无损原件。

## 6. 静默分析，不建设新的 Agent Runtime

固定数据处理管线：封口音频 → ASR → 说话轮次 / 事件切分 → 主题与事实提取 → 索引 / 巩固。

- ASR、切片、索引等固定工作可以由本机 worker 执行；它不规划任务、不注册行动工具、不运行 Agent 循环。
- 语义提取和反思使用宿主 Agent 的后台能力，或经明确配置的单次结构化推理任务。
- 宿主不支持后台调度时必须公开能力缺口：可继续采集并排队，不能保证闭着 Agent 也实时分析。
- 每项任务记录 pending / leased / succeeded / retryable_failure / blocked / superseded。
- 领取有 lease 与过期时间，写回带任务版本和来源内容哈希，拒绝陈旧结果和重复提交。
- ASR 不可用或不支持本地识别时显示待转写；未授权不能静默回退到云端上传。
- 每段音频都要有处理状态；纯音乐、静音或无法识别也要明确标记，而不是漏掉。
- 所有模型生成的主题 / 实体 / 推断都可重算；不能作为删除原件的依据。

## 7. 长期 Memory 方案

采用多层证据结构，而非只建一个“所有片段的向量库”，也不把月总结当作唯一长期记忆。

### L0 原始证据

音频轨道、桌面事件、完整转写、覆盖缺口。稳定 ID、内容哈希与可定位的 offset。

### L1 对话 / 经历事件

跨切片形成一个 episode：发生时间、人物候选、地点及来源、主题、原话片段、决定与承诺。
事件可重新分段；新版本保留指向原片段的引用。

### L2 实体与变化

围绕人、项目、方案和地点建立关联。分别保存事实有效时间和系统得知时间：
“周一答应周五交”与“周三改为下周一”并存，不能让旧承诺永久看起来仍然有效。
保留支持、反对、替代、完成记录；孤立的转写提及不能直接升级成用户偏好或长期事实。

### L3 可回溯的巩固记忆

生成事件组 / 项目阶段 / 人物摘要和未解决线索。支持增量更新、修正、重新索引和删除传播。
日 / 周 / 月总结是导航视图，指向原事件；摘要不是原始证据，也不是必须按日历切割的唯一组织方式。

### 检索

1. 用用户线索生成多个可检验的查询，不把含糊时间 / 地点强行当硬过滤。
2. 并行检索词面（全文 / BM25）、语义向量、实体关系和时间邻近；合并去重后重排。
3. 同时召回原始转写和巩固记忆，并扩展命中前后语境和相邻事件。
4. 用来源可靠性、明确程度、相关性与当时有效性判断；旧信息只因时间久不能自动失去召回资格。
5. 预算内交给宿主：证据片段、音频引用、覆盖范围、冲突与未知项。

数据库首版倾向本地 SQLite（元数据 / 全文 / 任务 / 引用关系）＋音频文件；
语义索引做可替换模块，避免一开始要求用户安装 Neo4j 或自建服务器。
具体中文分词、embedding 模型、索引规模和重排延迟需实测后选型。

## 8. 灵动岛交互

使用普通 macOS NSPanel 实现顶部入口，不声称获得 Apple 系统灵动岛 API。

- 收起：标识、录音来源和状态；不持续闪烁波形、滚动字幕或弹完成通知。
- 展开：开始 / 暂停、来源开关、当前地点标签、最近事件与待分析状态。
- 回忆：输入自然语言线索，展开候选事件、原话、音频位置和未完成事项。
- 执行：将查询和用户当前请求交给宿主 Agent；灵动岛不自行模拟对话或 Agent 推理。
- 边界：录音、等待分析、分析失败、暂停、权限缺失、空间不足、宿主离线必须不同。
- 支持无刘海屏、外接屏、菜单栏避让、多 Space 和全屏；不遮挡系统权限提示。
- 用户打开应用就能看见采集状态，有随手暂停和“删除最近一段”的入口；无隐形录音模式。

## 9. 数据访问与用户控制

音频在识别之前无法可靠判断是否含有密码或敏感谈话，不能套用文字正则后宣称绝无敏感原声落盘。
原生服务需提供显式启用、权限检查、锁屏 / 指定来源暂停、明显的录音状态和即时删除。
既有密码 / 支付等桌面禁止采集策略继续有效；不能仅凭前台应用假设系统音的所有来源都安全。

- 原始库本地保护；应用级加密、密钥管理与恢复机制未实现前不得宣传“已加密”。
- 录制同意、本地保存、云端音频上传和导出给宿主是分别记录的权限。
- 插件检索默认返回有限的文字证据和稳定引用，不把整天录音交给宿主。
- 现有“隐藏”影响检索与派生视图；新加入的“永久删除”必须覆盖原音、转写、摘要、向量和派生事实。
- 删除需要反向引用与失效传播；已导出或宿主已读取的副本不能宣称远程收回。
- 用户修正地点 / 人名是可溯源追加；永久删除与日记 append-only 不是同一种操作。
- 对周围人的告知方式、办公场景的录音约定和系统权限提示需在首次启用路径中明确。

## 10. 推荐借鉴及不直接照搬的部分

| 来源 | 借鉴 | AgentOne 的落地判断 |
| --- | --- | --- |
| [LongMemEval](https://arxiv.org/abs/2410.10813) | 事件分解、事实辅助索引、时间感知查询；评估更新与无法回答 | 为模糊线索、改口、跨对话整合、找不到时拒答建立专项测试 |
| [Hindsight](https://arxiv.org/abs/2512.12818) | 将经历 / 证据、实体摘要和观点分开；retain / recall / reflect | 推断保留来源，反思不变成无来源事实；不直接继承其基准分数作为产品效果 |
| [Zep / Graphiti](https://arxiv.org/abs/2501.13956) | 时间关系、动态事实、跨事件关联 | 使用有效时间 / 得知时间、失效与替代关系，不急于引入图数据库运维 |
| [Mem0](https://arxiv.org/abs/2504.19413) | 增量抽取与巩固 | 重要事实可巩固，但不能以“有用信息提取”替代用户要求的原声完整保留 |
| [Apple ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) | 系统音和麦克风输出配置与应用排除能力 | 分轨、权限与采样时间；须在支持的 macOS / SDK 版本实测，不把文档可用当作设备验证 |

以上是架构参考；这些文本对话基准不能证明长期环境录音、中文多人对话或跨月个人记忆已经可靠。
