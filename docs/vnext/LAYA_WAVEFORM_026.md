# 0.2.6：真实波形与 Laya 录音决策

## STATUS

已安装到本机 `~/Applications/AgentOne.app`（0.2.6），完成模型离线加载、听候 → 测试音自动恢复录音、真实音量变化和封口校验。远端 CI 状态以当前 PR 检查为准。

## DECISIONS

- 用户指定 [AWS Laya 实践](https://aws.amazon.com/cn/blogs/china/laya-service-validation-amazon-sagemaker/)。参考其 [本地封装](https://github.com/koljahuang/laya-local) 并核对 [官方模型与 SDK](https://huggingface.co/convaiinnovations/laya)。使用 Apache 2.0 多语言 checkpoint，CPU 单进程常驻，通过 stdin/stdout JSONL 调用 SDK，不增加 Agent runtime 或网络端口。
- 模型是文本分类器，接收真实 PCM 检测得到的“有声/持续安静/未知”描述；不直接识别语音、人物、谈话内容。录音保存/听候以 Laya 建议结合保守保护层决定。没有语音识别就无法判断声音是否值得记忆，此版不声称做到语义筛选。
- 只有模型连续两次选择 wait、所选答案概率 ≥0.75、双路输入正常、静音至少 15 秒并已录音至少 15 秒，才停止写文件；采样设备仍监听，保留最近 10 秒混音 PCM 到内存。恢复时先补回预录。等待超过预录长度的部分不落盘，在 coverage 中记录 `laya_wait` 缺口。历史文件不变。
- 模型不确定、缺失、离线加载失败或推理超时，继续保存原音。用户手动暂停、休眠、锁屏策略高于模型，旧 session 返回结果不能启动新 session。
- 本条用户的新要求替代 0.2.5“所有安静片段永久保存”的默认策略。单文件混合录音、MCP、事件记录和长期记忆接口继续保留。

## CHANGES

- 三处岛顶图标及录音卡均使用混音实际 RMS；12.5 Hz 读取，五柱展示连续实测值，无随机/正弦假动画。无新采样时 0.52 秒内回落；未录音时图标静止，遵循减少动态效果设置。
- 磁盘写入状态和设备监听状态分开；听候显示“听候中”，暂停按钮在两种状态都有效。
- 依赖由 uv.lock 固定，权重 revision 固定。`scripts/setup_laya.sh` 单独下载到用户 Application Support；App 启动只用离线缓存，不自动联网下载。打包携带分类脚本，退出时关闭自己的分类进程。
- 真机首次验证发现设备启动或回调计时延迟会误触 8 秒缓冲保护：混音定时器提前启动，合法主机时间戳延迟可分段追赶；真正未来时钟仍拒绝，新增真实 AAC 回归覆盖。
- MCP 状态含最近 capture_decision（选择、所选概率、实际是否保存、静音秒数、输入状态），无原音/转写；停止心跳的听候状态正确显示 offline。

## DEVICE VALIDATION

- UI 显示 `Laya 本机决策已就绪`，SQLite 最新决策为 wait、实际 saving=false、双输入正常；原生 UI 显示听候。未上传原音或转写给模型。
- 使用 QuickTime 播放本地 6 秒合成渐变测试音。先观测听候，再观测自动记录；连续 36 次 AX 采样中，实际混音音量从 0% 到 68% 出现多个不同值，结束后回落。测试音窗口已关闭。
- 最近三个封口文件均为 mixed，两个输入计数均大于零，SHA-256 正确，每份恰好一个 transcribe 任务；听候省略区间有 `laya_wait` 覆盖记录。历史音频未删除或重编码。
- 真机首次发现的时钟保护误触已修复并重新安装；再次验证已进入听候、自动恢复并正常封口。此观察不等于全天设备切换/休眠可靠性验收。

## HANDOFF

原始 Laya 零样本泛化较弱。保护层是必要边界；如果之后要按“交谈是否重要”选择录音，需要另行提供实时 ASR/声音语义模型输入并采集授权场景评估，不能从 RMS 推断人物或会议内容。
