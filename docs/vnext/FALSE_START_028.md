# 0.2.8：修复安静和未知状态误开启录音

## STATUS

已安装签名 0.2.8，完成静置、合成短声/持续声与回听候验证，修复未知/失败误开启路径。用户随后反馈现场会议未录到，说明这些测试不足以验收真实会议捕获；用户已明确选择持续本机保存，0.2.9 将原音保全与模型分析分离。定位系统认证已由用户完成，仅 AgentOne 获授权。

## ROOT CAUSE

用户反馈录音莫名开启。读取本机仅含数值/状态的最近决策发现：已安静十多分钟、inputs_ready=false，仍记录 model choice=record / saving=true。未读取用户原音、转写或地点。

0.2.6/0.2.7 有两个直接问题：默认 saving=true；等待时，只要不是高分 wait，就恢复写文件。模型加载、超时、低分及未知输入均可触发恢复。旧 prompt 还把“情况未知”列入 record，恰好强化该路径。单次 hasSound 又会保持约 3.5 秒，不能证明连续声音。

## DECISIONS / CHANGES

- 自动模式初始只听候，不创建录音文件。最近 3 秒的原生输入中至少 60% 的 200 ms 窗口达到 -42 dBFS、跨度至少 2.4 秒并有近期声响，才算持续声音；混音输出不重复计入证据。
- 单次碰撞、重复短声、未知输入、模型加载/错误/低分都不能开始。持续声音还必须配合两次 ≥0.75 record 判断，间隔 1.5～4.5 秒；生产每约 2 秒推理一次。重复同一时刻投票不计数。
- 开始和续录分开：已有录音保留静音尾段，至少记录 10 秒后遇 15 秒安静回听候；模型连续建议 wait 且无持续声音时可在 3 秒安静后结束。输入全部失联 5 秒结束。失败不会从听候自行恢复。
- 原来的显式手动持续录音保留，手动暂停和锁屏/休眠策略仍优先。听候的原音仅在 RAM 保留约 10 秒，确认后补回开头；省略时间记录 automatic_wait，旧历史不改写。
- 修正模型选项：未知/无持续声音属于 wait。送入模型的是标准化活动描述，不是原音或 ASR；不声称识别人声或说话人。
- MCP 状态增加实际持续声音、活动比例与可用输入来源，便于复核触发原因。UI 不再把加载/失败显示成“继续保留声音”。

## HANDOFF

固定音量门限仍可能将持续风扇噪声/音乐当作声音，也可能错过很轻或很短的对话。若需区别人声与环境声，应另行评估真正的音频活动/语义模型，不能把文本模型的概率当成声学识别能力。
