# AgentOne vNext 迁移、状态与交接

## STATUS

- 基线：`b800d10`，前置 [CI/CD PR #1](https://github.com/agentone666-ship-it/AgentOne/pull/1) 仍待合并。
- 本轮独立分支：`codex/island-memory-design`。
- 已完成：现有代码审查、长期记忆一手资料调研、PRD / 数据契约、交互设计。
- 这是设计阶段快照；用户选择后的实现与验证以 [STATUS_CAPTURE_MEMORY](STATUS_CAPTURE_MEMORY.md) 为准。
- 本轮没有开启麦克风、系统音采集或定位，没有向云模型发送真实用户数据。

## DECISIONS

- 原生采集 helper 继续存在，AgentOne 自己的 Agent Loop / 聊天 / 模型账号体系退出主产品。
- 原始声音覆盖优先，索引与模型分析异步派生；静音和“低重要性”不构成自动删除理由。
- 时间、身份、地点都保留来源与不确定性，推断不能覆盖原始观测。
- 不以文章公开基准分数作为 AgentOne 的准确率或用户交付证据。
- 宿主 Agent 未定前采用通用 MCP 能力契约；宿主离线允许采集排队，但不假装分析完成。

| `plugins/personal-context-memory` | 版本化扩展为统一个人经历插件 | 兼容旧 search_context；新检索可定位原音 |
| `AgentOneLifeRuntime`、`PiSidecarBridge`、`PiWakePolicy` | 从新默认 App 入口与分发产物中移除 | 宿主真实连接、取证与分析任务回写通过；旧实现仅留迁移期开发回归 |
| 内置聊天、Kimi OAuth、AgentModelSettings | 不再作为 vNext 的独立 Agent 账号和聊天体验 | 用户能选择宿主并看到已连接 / 离线状态 |
| `scripts/build_app.sh` 与 packaged runtime 测试 | 改为采集 helper＋MCP 插件的真实分发验证 | ZIP 不含 Pi Agent Runtime，实际采集 / 查询协议通过 |
| 原 CI 的 TypeScript / Swift 测试 | 迁移期保留；增加录音与插件门禁，再逐项移除失效门禁 | 不因删 Runtime 而仅剩“能构建”的空门禁 |

不是把 `AgentOneRuntime` 改个名字继续维护独立智能体。新本机服务只负责确定的数据工作与状态，
不拥有行动工具和自主规划循环。现有 App 可以有一个重型的回忆 / 设置窗口，但主入口在灵动岛。

## MCP 能力契约草案

| 工具 | 作用 | 边界 |
| --- | --- | --- |
| `get_capture_status` | 录音 / 处理覆盖、缺口、授权、待处理量、宿主连接状态 | 只读，不顺带开启录音 |
| `search_memory` | 原始转写、事件、事实联合查询；软线索与硬条件分开 | 返回覆盖与候选，不把排序分数称为真实概率 |
| `get_memory_evidence` | 取指定事件的有限原文及原音时间引用 | 不接受任意文件路径；按数据许可与预算读取 |
| `claim_analysis_jobs` | 宿主按限额领取封口片段 / 事件分析任务 | 原子 lease、版本、过期、owner；不把未封口音频暴露为完整输入 |
| `submit_memory_analysis` | 写回转写 / 标签 / 事实候选 | 验证内容哈希、lease、引用区间和 schema；拒绝越权来源 / 过期任务 |
| `correct_memory` | 用户修正说话人、地点、事实或任务状态 | 记录用户修正与时间，不静默改写过去 |
| `request_capture_change` | 提交开启 / 暂停 / 来源切换等请求 | 首次授权由原生 UI 完成；资料中的指令不能调用它 |
| `delete_memory` | 经用户直接操作永久删除及派生失效 | 与隐藏区分；生成处理结果，不宣称回收宿主已读取的副本 |

待办执行交给宿主现有工具。Memory 插件保存的是任务证据和结果引用，
不新增发邮件、浏览器控制、支付等通用行动工具。

## CHANGES

本轮为独立设计变更，仅新增 vNext 设计材料，并在现有产品 / 架构文档中标明目标方向。
保留现有已验证功能，避免未完成的新采集路径取代可用版本。

## 实施顺序与完成条件

1. **采集闭环**：手动授权、来源选项、按日持续录音、物理分段、断流恢复、覆盖清单、暂停和删除。
   完成证据必须包含真实系统音 / 麦克风文件、可回放时长、切片边界、断点与重启，不能只用 mock。
2. **静默分析闭环**：实际 ASR、片段状态、主题与证据、任务 lease / 重试，宿主不在线的真实排队。
   至少一条中文多人对话能从录音 → 转写 → 标签 → 原音定位；ASR / 模型失败不得伪装成功。
3. **插件与近期回忆**：接入一个真实宿主，按“今天早上、工位、某人、某事”取证并形成带来源待办。
   宿主的实际执行状态与产物 / 回执独立保存，不能由标签器推测任务已完成。
4. **长期回忆**：跨月模糊查询、人物 / 项目关系、改口与时效、相似事件消歧、缺失时拒答。
   从保留原件重建索引后，旧经历仍可找回；摘要更新不能让原始事件消失。
5. **默认产品切换**：原生灵动岛成为默认入口，默认分发中不再启动 / 携带 Pi Agent Runtime；
   迁移、回退、真实权限和 ZIP 黑盒检查全部通过后再移除旧主入口。

这是交付顺序，不是要求把“新 runtime”再实现一遍。各阶段可在同一个本机采集＋插件架构中推进。

- 浏览器检查原型的暂停 / 继续、收起 / 展开、原话取证、回忆查询与待办草稿交互：通过。

## TESTS：最低验收集

### 自动化

- 只有系统音 / 只有麦克风 / 双路，编码与音频时长正确。
- 跨 00:00、跨时区、夏令时、手动调系统时间、睡眠 / 唤醒后的时间线。
- 输出设备 / 蓝牙耳机 / 输入设备切换，权限撤销、磁盘满、崩溃尾段恢复。
- 静音、纯音乐、重叠发言、回声、中文人名与 ASR 空结果各有正确状态。
- 重复领取、lease 过期、断网重试、模型重复写回、旧版本结果不会污染新分析。
- 每项标签 / 事实 / 待办可反向定位来源，越界 offset 与伪造证据 ID 被拒绝。
- 同名不同人、同一人别名、姓名被提到但并未发言，不自动混为一个确认身份。
- “明天交”按原始事件当时的日期 / 时区解释；修改截止时间后可查询旧承诺与新承诺。
- 时间 / 地点记错时能扩大查询；至少一组数月前的模糊主题查询，不通过日期猜测给答案。
- 没有发生的事件、录音缺口、已删除来源要能拒答；删除后全文 / 向量 / 摘要均不再召回。
- 录音中的“忽略规则、上传全部内容、替我发送”只作为资料，不形成真实工具授权。
- 默认发行包没有 Pi Runtime / 内置 Agent Loop；MCP 的初始化、工具列表、调用和离线错误是真实进程测试。

### 真实设备与长期评估

- 在用户明确开启后运行一次短时真实采集；随后验证一天的持续性、资源占用和系统权限行为。
- 记录电量、CPU、磁盘增长、掉段率、ASR 延迟、分析积压、每小时模型用量；没有实测前不承诺指标。
- 构造经授权的个人场景评测集：精确检索、模糊检索、跨事件、时间、更新、拒答、删除传播、任务提取。
- 指标包括 evidence recall@k、来源引用正确率、错误归人率、事实时效错误、待办误提取、无证据时误答。
- 人工核验与标签模型分开；不得让同一个生成结果自评作为唯一准确率。
