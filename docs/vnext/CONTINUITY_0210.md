# 0.2.10 连续采集修复与真机验收

## STATUS

设备验收进行中。0.2.9 的短时双输入、文件封口和 CI 通过没有证明全程录音。用户提供的约 630 秒原视频已在本机与旧录音对照，确认有真实缺采集；完整视频提取音轨不能当作采集成功。

## 根因与证据边界

1. 更新退出会停止同进程采集，造成开头缺失；原生事件回调发生过实际崩溃，音频设备与编码器一起退出，造成中断。
2. AAC 容器在封口时才有完整索引，崩溃尾段不可直接播放。旧残片仅手工救回少量音频。
3. 写入队列延迟时，定时器按当前墙钟推进，会抢在排队的原生 PCM 回调之前填零，随后把真实采样当作迟到数据丢弃。
4. ASR 的 no_speech 不能证明没有声音。原视频尾部在另一个文件里有对应波形，但被转写漏识别。
5. 第一轮独立采集实验：PID/会话连续仍有采样迟滞，波形仅 800/1257 个有声窗口匹配，验收失败。采样回调与混音写盘必须分队列，后台录音需要禁用 App 小憩节流；分段还不能因处理延迟重新估计已知主机时间轴。
6. 本机默认输入曾为蓝牙耳机；AVAudioEngine 在重新安装输入 tap 时出现原生 Objective-C 异常，Swift `try` 无法捕获。用户要求仅使用 Mac 麦克风后，改为根据 CoreAudio 内置传输类型与输入能力匹配唯一设备 UID，用 AVCaptureSession 直接采集；不再安装 engine tap，不以默认输入或耳机作为恢复通道。

未上传原视频、录音、位置、转写或私有对照报告。私有原视频仅用于用户本机验收。

## DECISIONS / CHANGES

- 原生采集与界面、事件监听、ASR、模型分离。独立的小型原生监督进程重启意外退出的采集子进程；不提供 Agent 工具或聊天 runtime。
- 界面退出/重开重新接入同一个采集会话。界面明确“退出灵动岛（后台继续录音）”；暂停按钮仍停止采集，暂停意图持久保存，不因重开/恢复进程自行取消。
- 设备睡眠/锁屏通知由采集端处理，锁屏服从用户偏好；唤醒后按意图恢复。权限与存储失败明确显示，并进行有上限退避重试。
- 原音仍是一条混音。当前段先写私有 PCM 恢复日志，每秒同步，编码封口与索引成功后才清理。进程退出后，从真实 PCM 帧恢复 AAC，计算哈希、恢复时长和单份 ASR 任务；未采样区间仍保留缺口。
- 混音定时器只推进到已消费原生 PCM 的水位，避免覆盖还在排队的数据。采样信息通过私有快照提供给界面。
- 两路就绪输入取较慢水位，实际停流超过 3 秒才允许另一输入继续并记录缺口。原生输入回调只复制交接采样，实时优先队列负责混音与写盘；录音期间声明低延迟活动，仍允许用户真正休眠。
- 采集器使用独立 app bundle 身份，避免退出后重开界面时与后台采集器的 LaunchServices/辅助功能身份混淆。
- 用户已选择锁屏继续录音，本机“锁屏时暂停”关闭；这不改变其他安装的默认偏好。
- 麦克风固定 Mac 内置设备；接入耳机不改输入，设备不可用时明确告警并重试。录音元数据保存实际设备 UID、名称与选择策略，便于追查。
- 控制/状态文件 0600，拒绝符号链接，进程互斥锁防重复采集。诊断仅记生命周期、状态与错误，不记转写或原音内容。

## TESTS

- 界面采用现有会话、不重启音频；暂停后重开保持暂停；控制文件权限与链接拒绝。
- 延迟定时器不得抢先填零，后续排队音频不丢帧。
- 一路先到、另一路排队时，先到的输入不能推进封口覆盖后到的麦克风采样。
- 真实子进程 `_exit(77)` 跳过所有音频析构，2 秒 PCM 尾段恢复为可读 AAC，96,000 帧、来源哈希与单份转写任务通过。
- 本地回归：144 个 Swift 测试、21 个 MCP 测试、56 个 legacy runtime 测试通过；原生 AAC → SQLite → MCP 联调、真实崩溃夹具恢复及 Release ZIP 签名/资源/版本/独立 helper 自检通过。
- 已安装版本的真实录音元数据确认 `BuiltInMicrophoneDevice` / `mac_builtin_only`；默认输入仍为蓝牙耳机时，实际录音使用内置设备。整段播放过程中退出并重开 UI，原生 PID/会话不变。
- 第二轮原视频实录：3037 次健康快照无告警，UI 退出/重开同一采集会话；原始混音 NCC 为 1204/1257，53 个低相似窗口不能标成严格波形全通过。低信噪比窗口仍需校准输入验收，原失败报告仅本机保留。不能把原视频直接导入数据库冒充录制。

## 本机端到端验收步骤

1. 安装后确认后台实际收到系统音/麦克风采样，等待输入就绪。
2. 从 0 秒完整播放用户约 630 秒原视频，不在播放过程中安装或重启采集。
3. 中途退出并重开灵动岛，核验采集 PID/会话不变。
4. 保留播放前后余量，等待末段封口，按墙钟拼接真实已封口文件。
5. `benchmarks/capture/compare_recording.py` 做源音频与录得音频的波形对照。每 0.5 秒检查一个 1 秒有声窗口，要求首尾与全部有声窗口达到相似度门槛；不以 ASR 文本、时长或文件个数替代。

停机、权限关闭、硬件不可用时的声音无法凭软件补回；验收结论必须限定到实际执行的场景。

## 追加故障定位

原视频播放完毕后，长时间观察出现会话重建；实际采集器当时仍是同源 Debug 进程，不能把替换磁盘上的 Release 包等同于运行中进程已升级。补充第一故障和存储操作错误日志，并修复延迟关闭超过 30 秒时封口失败：只封口实际已收 PCM，未采样尾段明确记录缺口，不填零伪造。新增 61 秒关闭延迟测试通过。最终验收需真正重启到 Release 采集器。

## 卡死与可分发安装包修复

- 实机出现过进程存活但状态文件、PCM 文件均停止更新。异步框架等待不一定表现为进程崩溃；不把存活 PID 或过期 `recording=true` 视为真实采集。系统音设备查询/启动/停止加入独立截止时间，非协作等待不会使超时本身继续等待。
- 监督进程与采集进程分开，检查控制心跳和每秒实际 PCM 写盘脉冲；控制线程卡死或写盘停滞时终止并重建采集子进程，仍恢复持久暂停意图。首次系统授权保留等待时间，手动暂停可以终止失去响应的授权/采集进程。
- 新增不请求录音权限的真实监督自检：启动停更的独立睡眠进程，确认看门狗终止它、启动不同 PID 的替代进程，并清理测试子进程。
- CI 分发产物暴露 SwiftPM 资源定位错误：构建机器上的绝对 build-path 回退掩盖了 `Contents/Resources` 未被读取。改为优先读取 app 内资源，打包 app 不允许使用构建目录回退；自检会隔离移走资源并重新签名测试副本，要求明确失败，不能继续从构建目录读取。
- 灵动岛在后台状态过期时保持警告，即使已经不是 listening；恢复后清除已过时的启动失败状态。
- 上述新增修复的端到端校准、最终构建和 CI 结果待验收后补充。早先 144 Swift 测试和旧版本实录不代替这些新增修复的验收。

暂停改为带 nonce 的后台确认；旧的未录音状态不能确认新暂停命令。监督进程对未确认暂停单独计时，即使状态心跳仍新鲜或首次启动仍在等待授权，也会强制结束不响应的子进程，再以暂停意图重建。新增实际进程暂停监督自检；智能听候期间无文件写入是正常状态，不误触写盘看门狗。

模型审计元数据改用独立、零等待的 SQLite 连接，在音频队列之外尽力写入，拒绝旧时间戳覆盖新状态。数据库繁忙或模型概率非法不能触发采集停止。新增真实 SQLite 写锁夹具：审计写入失败时，已开启的混合 PCM 继续写入并成功封口。CI 曾暴露主线程 UI 测试使静态假心跳过期；测试假后台改为独立心跳，超时测试检查底层操作尚未完成而调用已返回，不以繁忙 UI 主线程的墙钟耗时判定。
