# 0.2.5 系统音与麦克风合并录音

## STATUS

用户最新要求：“系统和麦克风都合并到一起，不用分开录”。这取代此前分别保存两路的决定。

已完成本机 0.2.5 安装和设备短录验证，继续自动记录。自动记录、事件采集、本机转写与原音访问偏好保留。

## DECISIONS / CHANGES

- 新录音先按同一 host clock 对齐两种输入，再混成一个立体声 AAC 流；每段只生成一个文件、一份转写任务。MCP source 为 `mixed`。
- 两个输出声道都包含系统音和麦克风。保留系统的左右声道，麦克风混入左右两边；不是左边只录电脑、右边只录麦克风。输出 48 kHz，两个输入各 0.5 增益，避免正常幅值直接相加溢出。
- 输入采样率不同则按主机时间线性重采样；1.5 秒缓冲接收异步/乱序包，串行队列每 100 ms 推进。没有输入的时段填零占位，后面的声音不会被挤到前面。
- 缺少输入的时长、迟到帧、增益、采样率和混音模式保留在覆盖记录/元数据中。所有缺帧累计统计，超过 10 ms 的输入缺口独立持久化。迟到已写区域的采样不倒改已封口文件及哈希。
- 有限缓冲和异常时钟/写入错误会停止并显示原因，避免无限缓存或伪造连续完整录音。
- 当前不做声学回声消除或说话人识别；混音后的声音不能拆回原来两路独立原件。
- UI 显示一张“系统声音＋麦克风／合并录音”卡片，回忆页新条目标注“混合录音”。
- 旧分轨文件、ID、哈希、转写、任务和长期记忆引用保留，不自动重新编码或删除。旧条目明确标为历史系统音/麦克风。
- schema v2 扩展 mixed 来源，v1 升级在同一事务中保留数据和引用。外键检查失败则回滚为旧结构；升级脚本由 Swift 和 Node 共享，完成后恢复外键检查。
