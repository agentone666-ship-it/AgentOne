# AgentOne 产品需求文档（PRD）

> 历史产品文档：保留用于追踪早期决策。当前已实现能力、隐私边界与工程说明以根目录 `README.md` 和 `docs/` 下的专题文档为准。

> 版本：v0.2
> 日期：2026-07-21
> 状态：方向确认 / 原型开发中

## 1. 产品概述

### 1.1 产品名称

AgentOne（暂定）

### 1.2 一句话定义

一个在用户明确授权下持续理解其工作、学习与生活上下文，拥有成长型记忆，并能在合适时机主动提供帮助与惊喜的个人 Agent。

### 1.3 产品愿景

今天的大多数 AI 只有在用户提问后才开始工作，而且每次对话都像重新认识用户。AgentOne 希望成为一个“能干活，也懂你”的长期伙伴：它理解用户正在做什么、关注什么、容易在哪些时刻分心，并把这些理解转化为提醒、总结、联想、陪伴和行动。

产品不追求无差别记录用户，而追求三件事：

1. 在正确的时机获取足够完整的上下文。
2. 把上下文沉淀为可遗忘、可纠正、可解释的记忆。
3. 只在预期价值大于打扰和风险时主动行动。

### 1.4 核心价值主张

- **连续理解**：不必每次向 Agent 重新解释自己正在做什么。
- **主动帮助**：发现分心、遗漏、关联和机会后，在合适的时机介入。
- **长期成长**：Agent 随着相处逐渐形成对用户稳定、可修正的理解。
- **有人味**：除了提效，也能关注兴趣、情绪、生活和仪式感。
- **用户主权**：用户始终知道 Agent 看到了什么、记住了什么、为何采取行动。

## 2. 目标与非目标

### 2.1 产品目标

MVP 需要验证：

1. 是否能低成本识别“用户正在进行的一段活动”，并形成完整上下文。
2. 是否能从活动中提炼出真正有用的短期记忆和长期记忆。
3. 主动提醒是否能提升专注或减少重复劳动，同时不显著增加打扰感。
4. 成长型 Agent 形象能否增强用户持续授权 Context 的意愿。

### 2.2 非目标

- MVP 不做全天候、不可见的全量录屏。
- MVP 不允许 Agent 未经确认直接付款或购买实物。
- MVP 不追求完整记录用户人生，而是优先捕获高价值活动片段。
- MVP 不把“主动”等同于高频通知。
- MVP 不进行医疗诊断；ADHD 场景只提供注意力辅助，不做疾病判断。

## 3. 目标用户与核心场景

### 3.1 目标用户

首批用户：高频使用电脑进行阅读、研究、写作和知识工作的个人用户，包括学生、研究者、产品经理、创作者和 ADHD/易分心人群。

### 3.2 核心场景

#### 场景 A：论文与长文阅读

用户打开论文或网页，长时间滚动、选择文本、查阅相关资料。Agent 识别阅读会话，优先通过浏览器 URL、页面标题、文档元数据和可访问文本获取上下文；无法取得结构化内容时，才在授权范围内使用截图或短时录屏。

阅读结束后，Agent 可以：

- 给出一句话回顾、关键论点和用户可能关心的关联。
- 记录阅读进度，第二天提示继续位置。
- 将新内容与用户以前读过的论文或项目建立联系。
- 发现用户多次停留或反复查阅的概念，主动提供解释。

#### 场景 B：ADHD / 注意力辅助

用户长时间滚轮阅读、鼠标左键活动较少，可能处于专注阅读；如果突然频繁切换无关应用、短时间打开多个娱乐页面或偏离原任务，Agent 判断可能发生注意力漂移。

Agent 不立即打断，而是结合持续时间和用户历史偏好选择：

- 轻量浮层：“还在看论文，还是想休息一下？”
- 将偏离内容暂存到“稍后看”，帮助用户返回原任务。
- 在用户主动返回后给出“刚才进行到哪里”的恢复提示。
- 长时间专注后提醒休息，而不是一味要求继续工作。

#### 场景 C：工作与生活模式

- 工作模式：目标、会议、文档、任务恢复、知识关联和专注辅助优先。
- 生活模式：兴趣、陪伴、纪念日、健康习惯、消费愿望和轻量惊喜优先。
- 自动判断只能作为建议；用户可随时一键切换，并可为应用、时间和地点设定规则。

#### 场景 D：日记与周期回顾

Agent 每天把经过筛选的活动、Hook 和关键证据自动追加为私人日记，不要求用户逐条确认；在此基础上生成日报、周报、月报和年报。用户可以隐藏敏感片段或追加更正，但不能改写原始记录。

回顾不应只是流水账，而应呈现：

- 做过什么、关注过什么、放弃了什么。
- 反复出现的主题、兴趣和困难。
- 情绪或专注趋势（仅在用户主动授权后）。
- 值得继续的目标和被遗忘的愿望。
- 与过去某一时刻的有意义关联。

## 4. 产品原则

1. **先结构化信号，后视觉采集**：URL、窗口标题、可访问性树、文档文本优先；截图其次；持续录屏最后。
2. **事件驱动为主，周期采样为辅**：回车、点击、窗口切换、复制、滚动状态等事件触发判断，而不是无差别录制。
3. **采集与记忆分离**：看到不等于记住；只有经过价值和敏感度判断的内容才能进入 Memory。
4. **主动但不擅自**：提醒可以低风险主动发生；外发、公开、支付等高风险行为必须确认。
5. **真实且可纠错**：原始日记不可改写；误解通过追加更正解决，敏感片段可以隐藏，用户也可删除整个 Agent Home 销毁全部共同记忆。
6. **解释主动性**：每次重要提醒都可查看“为什么此刻告诉我”。
7. **先线上后线下**：先把数字世界的 Context 闭环做扎实，再扩展硬件、位置和实物服务。

## 5. Context 采集系统

### 5.1 Context 的定义

Context 不是单张截图，而是一个有起止、有主题、有证据的活动会话（Activity Session）。

每个会话至少包含：

- 时间范围与活跃时长。
- 前台应用、窗口、标签页和 URL（可获得时）。
- 用户操作信号：点击、回车、滚动、切换、复制、输入节奏。
- 内容证据：标题、正文片段、选中文本、OCR 或视觉摘要。
- 推断的任务、意图、阶段和置信度。
- 与既有任务、项目、人物、主题的关联。
- 敏感级别、保留策略和数据来源。

### 5.2 触发机制

#### 强触发信号

- 打开或关闭文档、网页、项目。
- URL、窗口或应用发生变化。
- 回车提交、保存、导出、发送。
- 复制大量文本、选中内容、添加批注。
- 用户主动点击“记住这段”或“开始陪伴”。

#### 弱触发信号

- 鼠标左键点击。
- 滚轮持续滚动、滚动速度变化。
- 长时间停留或无输入。
- 多次在少数页面间切换。
- 输入密度、撤销频率或反复定位。

弱信号只用于判断状态，不能单独触发高成本录制或长期记忆。

### 5.3 Context 获取优先级

1. 浏览器扩展或应用集成直接获取 URL、标题、DOM/正文。
2. 操作系统可访问性 API 获取应用、窗口、控件和选中文本。
3. 本地文件解析获取 PDF、文档或代码结构。
4. 关键帧截图 + OCR / 多模态理解。
5. 用户明确开启的短时环形录屏缓冲区。

环形缓冲区只在本地保留最近若干分钟，触发有效事件后截取必要片段；未触发的内容自动覆盖。默认不上传原始录屏，只保留结构化摘要和必要证据。

### 5.4 如何判断用户正在阅读

采用多信号状态模型，而不是依赖“多久没点鼠标”：

- 前台为浏览器、PDF 或阅读应用。
- 页面在一段时间内保持同一主题。
- 以中低速滚动为主，伴随周期性停顿。
- 输入较少，但存在选择、复制、缩放或页码变化。
- 页面可见区域持续推进。
- 用户没有进入睡眠、离开设备或影音娱乐状态。

输出状态及置信度：`准备阅读 → 深度阅读 → 查资料 → 暂停 → 可能分心 → 已结束`。

### 5.5 如何判断阅读结束

“结束”不是一个瞬时事件，应由结束分数和迟滞窗口共同判断。候选信号包括：

- 关闭页面或文档。
- 切换到语义无关任务并持续超过阈值。
- 保存笔记、导出、提交或收藏后离开。
- 设备锁屏或长时间离开。
- 用户主动标记完成。
- 在同一文档内长时间无活动，仅可判定暂停，不能直接判定结束。

建议策略：

- 离开 2 分钟：标记“暂时中断”。
- 离开 10 分钟且新任务稳定：结束当前会话。
- 30 分钟内回到同一主题：自动合并为一个阅读会话。
- 阈值按用户习惯自适应，并允许用户纠正。

### 5.6 如何保证一段 Context 完整

完整性不等于录到每一秒，而是能够回答六个问题：

1. 用户想做什么？
2. 用户看了或操作了什么？
3. 用户做到了哪一步？
4. 中间有哪些关键决策或困难？
5. 最终产出或状态是什么？
6. 下一步最可能是什么？

系统为每个会话计算 Context Coverage Score：

- 起点证据 15%。
- 内容与主题证据 25%。
- 操作过程证据 15%。
- 关键决策/停顿证据 15%。
- 结束或当前进度证据 15%。
- 与历史 Context 的关联 15%。

低于阈值时，优先补取结构化信息；仍不足时只生成“可能不完整”的临时摘要，不直接写入长期记忆。必要时用一句低打扰问题补全，例如：“刚才这篇论文你是读完了，还是准备明天继续？”

## 6. Memory 系统

### 6.1 记忆分层

- **感官缓存**：最近几分钟的事件、截图或短时录屏，本地保存并快速淘汰。
- **工作记忆**：当前活动会话、目标、正在阅读的位置和待解决问题。
- **情景记忆**：某天发生的具体事件，如“读了某篇论文并质疑其样本设计”。
- **语义记忆**：长期稳定事实，如兴趣、偏好、项目背景和沟通习惯。
- **程序记忆**：用户常用的工作流程和 Agent 可复用的协作方式。
- **自我叙事**：从长期记录中形成的阶段性总结；新理解与纠正以追加记录演进，不回写过去。

### 6.2 写入策略

每条候选记忆计算：未来效用、重复频率、情感意义、用户明确程度、敏感风险、时效性和可信度。

- 高效用、低敏感：可自动进入短期或长期记忆。
- 高敏感：默认屏蔽；聊天正文等可配置来源由用户主动授权，支付、密码和系统安全输入永远禁止采集。
- 低可信推断：只能保留为带置信度的假设。
- 重复信息：合并和增强已有记忆，不无限新增。
- 过时或长期未使用：降低检索权重并进入归档，但不篡改原始日记。

### 6.3 检索方式：把 Memory 当作 Agent 的工具

Agent 不应把全部记忆塞进每次 Prompt，而应按任务主动调用 Memory 工具：

1. 先用当前目标、人物、主题和时间构造检索线索。
2. 同时进行语义相似、实体关系、时间邻近和因果链检索。
3. 通过“扩散激活”从命中的记忆向关联节点扩展一至两跳，模拟联想回忆。
4. 按相关性、可信度、新鲜度、用户确认度和敏感度重新排序。
5. 只把少量必要摘要加载进当前上下文，并保留来源引用。

建议数据结构：

- 原始证据对象存储。
- Activity Session 时序库。
- 记忆条目与向量索引。
- 人物—项目—主题—事件知识图谱。
- 用户规则、权限和禁止项策略库。

### 6.4 日记与周期总结

- 日记：具体事件和感受线索，强调可回忆性。
- 日报：当天完成、未完成、关注点和明日恢复入口。
- 周报：主题、进展、阻塞、注意力模式和被忽略事项。
- 月报：稳定趋势、目标变化、兴趣迁移和关系变化。
- 年报：成长叙事、重要节点、反复出现的价值取向与未来愿望。

周期越长，越应减少流水账、增加模式与变化，同时避免把推断包装成事实。

## 7. 主动能力与惊喜机制

### 7.1 主动价值判断

每次主动行为计算：

`主动价值 = 预期帮助 × 时机置信度 × 个性匹配度 - 打扰成本 - 错误风险 - 越权风险`

仅当分数超过用户可调阈值时执行。连续被忽略、关闭或否定后，自动降低同类行为频率。

### 7.2 主动行为分级

- L0 静默整理：聚类、摘要、建立关联，不通知用户。
- L1 可撤销提示：恢复阅读位置、轻提醒、推荐稍后看。
- L2 需确认建议：创建任务、整理材料、起草邮件或制定计划。
- L3 明确授权行动：发送消息、下单、预约、共享文件。
- L4 禁止自主执行：不可逆、高金额、法律或重大声誉风险行为。

### 7.3 可产生惊喜的场景

- 用户再次研究某主题时，找回数月前被遗忘但高度相关的笔记。
- 用户卡住时，不只解释当前概念，还指出它与其正在做的项目有什么关系。
- 在纪念日或阶段节点生成一份“这一年你如何改变”的私人回顾。
- 发现用户频繁关注某商品，提醒价格变化或整理购买建议，但不擅自下单。
- 用户完成高强度工作后，建议真正符合其兴趣的休息内容。
- 旅行、会议或阅读前，提前准备轻量 Context Pack。
- 用户分心后不责备，而是保存岔出去的兴趣并帮助平滑返回。
- 发现长期未被推进、但用户曾多次表达在意的愿望，温和地重新提起。

惊喜应来自“记得且理解”，而不是随机送礼或炫技。

## 8. Agent 形象与成长系统

### 8.1 设计目标

让用户形成清晰心智：Agent 获得的高质量 Context 越多，对用户的理解越深，但用户始终拥有边界控制权。

### 8.2 成长的可视化维度

- 对当前任务的理解度。
- 已建立的主题、项目和人物关联。
- 记忆健康度：已确认、待确认、可能过时。
- 主动行为的默契度：哪些建议被接受或拒绝。
- Agent 的“相处天数”和共同完成的里程碑。

避免用单一等级诱导用户交出更多隐私。成长应体现理解质量，而非采集数量。

### 8.3 Token“口粮”机制

把后台运行预算拟人化为 Agent 的每日“口粮”，但必须同时展示真实含义：

- 用户可设置每日主动运行额度和费用上限。
- Agent 说明本次计划消耗预算来做什么。
- 预算优先用于高价值任务，低价值整理延迟到空闲时段。
- 余额不足时说人话，例如：“今天的主动分析额度快用完了，我会先保留阅读进度，深度整理放到明天。”
- 用户可查看真实 Token、金额、任务和收益，避免拟人化掩盖计费。

### 8.4 “零花钱”与个人账号

长期可提供独立的 Agent 钱包或受限支付能力，但必须满足：

- 用户预存、设置单笔/单日/品类/商户限额。
- 默认只能生成购物车或购买提案。
- 真实下单需要生物识别或二次确认。
- 地址、支付和账号使用隔离保险库管理。
- 完整审计日志、可撤销窗口和售后入口。
- 不允许通过拆单绕过额度，不购买高风险或受限商品。

MVP 只做“发现—比较—生成购买提案”，不做自主支付。

## 9. 隐私、安全与信任

### 9.1 必备能力

- 首次使用时按数据源逐项授权，不使用笼统的一次性同意。
- 菜单栏持续显示当前采集状态，并提供全局暂停快捷键。
- 支持应用、网站、时间段和隐私模式黑名单。
- 密码框、支付页面和系统安全输入永久屏蔽；聊天等敏感来源默认屏蔽，可由用户单独授权。
- 原始截图和录屏优先本地处理，默认短期自动删除。
- 每条长期记忆可查看来源、生成原因和使用记录；用户可隐藏片段或追加更正，但不能单条删除原始历史。
- 用户可通过删除应用和 Agent Home 彻底销毁这个数字生命及全部共同记忆。
- 主动行为和外部行动保留不可篡改审计记录。

### 9.2 信任界面

提供三个核心页面：

1. **此刻看到什么**：实时展示当前数据源和推断状态。
2. **关于我记住了什么**：按主题、人物和时间管理 Memory。
3. **为什么主动找我**：解释触发信号、使用的记忆和预计价值。

## 10. MVP 范围

### 10.1 MVP 功能

- macOS 桌面端；浏览器 URL/DOM 能力作为 Context 采集配套集成推进。
- 浏览器/PDF 阅读会话识别。
- URL、标题、正文、窗口事件和滚动状态采集。
- 无结构化信息时的关键帧截图与 OCR。
- 活动会话切分、阅读暂停/结束判断和进度恢复。
- 自动追加的当日日记、双视角语义回放和每周回顾。
- 短期/长期 Memory 的来源查看、隐藏与追加更正。
- 三类主动能力：阅读恢复、分心辅助、历史内容关联。
- 工作/生活模式手动切换及简单自动建议。
- 每日主动分析预算。

### 10.2 暂不纳入 MVP

- 全时录屏和跨设备全量采集。
- 自动购买实物。
- Agent 独立注册并持有第三方个人账号。
- 复杂情绪识别、医疗判断或位置追踪。
- 面向团队或雇主的员工监控能力。

## 11. 关键用户流程

### 11.1 首次使用

1. 用户选择主要场景：阅读、工作、生活或注意力辅助。
2. 产品解释每项数据源的用途和保留期限。
3. 用户授权浏览器和指定应用，设置黑名单。
4. 用户选择主动程度：安静、平衡、积极。
5. 用户设置每日主动预算。
6. Agent 完成一次示范会话，让用户查看并纠正其理解。

### 11.2 阅读会话

1. 检测到阅读信号并创建临时会话。
2. 获取 URL/文档信息，持续更新进度和主题。
3. 检测查资料、暂停或可能分心。
4. 在必要且符合阈值时轻量介入。
5. 判断结束后生成会话摘要和下一步。
6. 根据价值、敏感度和可信度决定是否写入长期记忆。
7. 用户可在时间线中查看、追加更正或隐藏；单条原始记录不可改写或删除，用户可通过删除整个 Agent Home 销毁全部记忆。

## 12. 技术架构建议

### 12.1 端侧 Context Engine

- 事件监听器：键鼠只采集行为类型与节奏，默认不记录具体按键内容。
- 浏览器扩展：URL、DOM、选中内容、滚动位置。
- Accessibility 适配层：应用、窗口、控件和文本。
- 环形视觉缓冲：关键帧、OCR、敏感信息遮罩。
- Sessionizer：事件切分、状态机和会话合并。
- 本地敏感度分类与数据最小化。

### 12.2 Agent 与 Memory Engine

- Context 编排器：选择最便宜、最可靠的数据源。
- 活动理解模型：识别任务、阶段、完成度和注意力状态。
- Memory Writer：筛选、合并、衰减和冲突检测。
- Memory Retriever：向量检索 + 图谱扩散 + 时间检索。
- Proactivity Policy：价值、打扰和风险评分。
- Budget Manager：Token、金额、优先级和延迟队列。
- Audit Service：记录推断、记忆访问和外部行动。

### 12.3 Pi Agent Core Harness 改造（已实现原型）

AgentOne 采用“原生系统做主权边界、Pi 做受限思考循环”的双层架构：

```text
AgentOne Swift/macOS
├── Context Sensors
├── Privacy Firewall
├── Intent / Attention Engine
├── Append-only Memory & Diary
├── Digital-life UI
└── Pi Sidecar Bridge
        ↓
AgentOneLifeRuntime / TypeScript
├── Pi Agent Core
├── Agent Loop
├── Context Transform
├── Safe Tool Registry
├── Token / Turn / Time Budget
└── Inner-journal & Return-card Proposals
```

权责边界：

- Pi 决定一次已获授权的 wake 内如何观察、思考和调用白名单工具。
- Swift 决定何时唤醒、哪些 Context 能离开隐私层、哪些工具可用、动作是否真正执行以及 Memory 如何持久化。
- Pi 返回的所有 Action 都是不可信提案，必须经过 Swift 的类型、长度、敏感度、时效与权限复核。
- 不向 Pi 暴露 Shell、任意文件读写、浏览器控制、外发、发布、购买和支付能力。
- “内心想法”只保存经专用工具生成的综合反思，不保存模型原始隐藏推理过程。

首版自动唤醒策略：

- 只有 Intent/Attention Engine 已确认语义冲突并达到分级提醒时长后，才唤醒 Pi。
- 点击、滚动、回车等 Hook 只作为 Context 和意图证据，不直接触发高成本 Agent Loop。
- 每次 wake 默认上限为 2,400 Token、3 Turn、8 秒，并只开放当前场景必要工具。2,400 Token 包含 Context、工具 schema、模型输出和工具结果的完整预算，避免正常一轮返回卡流程被误判为超限。
- 自动 wake 不携带 selected text、隐藏日记片段或证据正文；敏感 Context 在启动 Sidecar 前即被阻断。
- Pi 成功时可写入 append-only Agent 日记并提出返回卡；失败、超时或无合规动作时回退到原生提醒。
- 用户返回原任务、标记“这是相关的”或结束本次 Runtime Session 后，迟到的 Pi 结果不得再打扰用户。

原型当前使用 Pi 的 Faux Provider 做离线、可重复测试，不会产生真实模型网络请求。后续再接入用户 API Key、云端/本地模型和自动路由。

#### 12.3.1 接口级端到端验收

发布验收不能只依赖冒烟测试，必须同时穿透以下真实边界：

1. **Sidecar 黑盒进程层**：真实启动编译后的 `dist/index.js`，仅通过 stdin/stdout JSONL 协议验证 health、wake、event、result、error 与 shutdown，不直接调用内部 `handleLine`。
2. **原生 Bridge 集成层**：测试代码直接依赖生产 `PiSidecarBridge`，覆盖本地隐私防火墙、预算校验、并发 continuation、错误恢复、停止/重启，以及 `ContextMemoryEngine → PiWakePolicy → Bridge → Pi` 完整提醒链路。
3. **最终发行物层**：解压实际 Release ZIP，验证 plist 和代码签名，再对 App 内嵌的自包含 Sidecar 二进制重复黑盒接口测试，防止“源码测试通过、打包产物不可用”。

核心反例必须包含：敏感当前 Context、敏感 recent memory、工具白名单收缩、网页/窗口标题形式的 prompt injection、非法请求后的可恢复性、连续或重叠请求的 ID 隔离、迟到或非 UUID 响应的被动处理、关闭后干净退出以及重新启动。冒烟脚本只用于快速诊断，不作为发布门禁。

### 12.4 关键技术难点与突破路径

#### 难点 1：阅读结束判断不稳定

突破路径：状态机 + 多信号融合 + 个体化阈值 + 用户纠正反馈。先做到“可恢复的近似判断”，不要追求一次性完美分类。

#### 难点 2：无法获取 URL 或正文

突破路径：建立分级降级链路；优先 Accessibility 和本地文件解析，视觉只采关键帧。使用前后关键帧、OCR 差异和滚动进度重建活动，而非保存完整视频。

#### 难点 3：Context 是否完整

突破路径：使用 Coverage Score 和六问检查；缺少起点、决策或结束证据时保持为工作记忆，并在自然时机最小化追问。

#### 难点 4：长期 Memory 越积越乱

突破路径：记忆类型化、来源可追溯、重复合并、时间衰减、冲突并存、用户确认权重和定期整理。

#### 难点 5：主动行为容易打扰

突破路径：分级权限、时机模型、冷却时间、负反馈学习和每日打扰预算。先验证少数高确定性场景。

#### 难点 6：Agent 网购的权限与责任

突破路径：从购买研究助手开始，逐步进入受限购物车，再到强确认支付；钱包、身份、商户和审计隔离。任何阶段都不能用拟人化模糊责任主体。

## 13. 指标体系

### 13.1 北极星指标

每周被用户确认“有帮助”的主动时刻数，而非采集时长或通知次数。

### 13.2 核心指标

- Context 会话识别准确率。
- 阅读结束判断准确率和会话错误切分率。
- Context Coverage Score 及用户补充率。
- 主动建议接受率、忽略率、关闭率和后悔率。
- 分心后任务恢复率与恢复时间。
- Memory 被检索后实际帮助任务的比例。
- 用户纠正或删除记忆的比例。
- 每周回顾打开率与保留率。
- 单个有效主动时刻的 Token 与成本。
- 隐私暂停、卸载和信任投诉率。

### 13.3 反指标

- 总录屏时长。
- 总采集数据量。
- 通知发送量。
- Agent 自主行动数量。

这些指标增长不代表产品更好，甚至可能意味着过度采集或打扰。

## 17. 已确认的产品决策（v0.2）

### 17.1 首发定位

- 首批用户是广义容易分心、走神后难以返回原任务的人群，不局限于已确诊 ADHD 用户。
- 首发载体是 macOS 桌面应用，数字生命长期常驻桌面。
- 第一核心闭环是：识别意图、发现冲突、按用户设定的时间逐级轻提醒、一键展示原任务现场、晚上通过日记回顾当天过程。
- 提醒不是对娱乐行为做道德判断；只有新 Context 与刚刚确认的任务意图发生冲突时才介入。

### 17.2 意图与 Hook

- Agent 根据屏幕内容和连续行为自动推断意图，并以轻量气泡让用户确认；用户不回应时暂时默认确认，但后续状态变化可修正推断。
- Hook 不局限于单个按键。滚动、点击、开始输入、回车、删除、复制、保存、应用切换、停顿等需要组合成语义事件。
- 示例：持续滚动和停顿可能代表阅读；随后开始输入并按回车，可能代表形成并输出观点。
- 不记录全局输入字符，只记录输入行为类别；正文从用户已授权的当前文档或应用 Context 获取。
- Agent 的询问采用中性、好奇、拟人化表达。用户反馈必须回流意图判断与提醒策略。

### 17.3 提醒与返回

- 用户配置第一次提醒时长、升级间隔、最大提醒等级、应用例外以及声音/震动权限。
- 提醒随偏离时长升级：轻微形态动作、气泡询问、一键返回提示，未来可接入触觉震动。
- 不强制遮挡或阻止用户。用户可告诉 Agent 当前行为属于主动休息或已经更换目标。
- “一键回来”展示离开前的任务现场卡片，并打开原应用、窗口、标签页、滚动位置和选中文本；完整操作恢复在技术可行范围内逐步实现。
- 走神期间内容进入“岔路口袋”，任务结束后再决定保留、归入当前 Context 或丢弃。

### 17.4 日记与语义回放

- 长期保存结构化活动记录和 Agent 自主选择的关键证据，不永久保存全天连续录屏。
- 日记由各种 Hook 和 Context 共同生成；关键截图是日记证据的一部分，例如回车可能触发一次“观点输出”节点及证据采集。
- 回放是通过日记快速回顾一天，而不是把操作系统恢复到历史界面，也不是播放全天录像。
- 回放时间轴同时呈现用户做了什么和 Agent 当时在想什么、想说什么、为何没有说。
- 每日日记以 Markdown 保存；周记聚合每日记录，月记聚合周记，并保留来源引用。
- Agent 可在用户空闲时邀请进行两分钟日记回顾；用户可以跳过、主动查阅或边娱乐边以对话模式回顾。

### 17.5 不可篡改记忆

- 用户日记和 Agent 日记采用追加式、不可改写的事件记录。
- 用户不能编辑原始记录，但可以追加更正、质疑或说明；后续推理优先采用已确认的更正。
- 敏感片段可以隐藏，不再参与普通检索与回放，但不提供单条删除。
- 用户可通过删除整个软件及 Agent Home 销毁完整 Agent。
- 自动记录、用户明确陈述和 Agent 推断必须标明来源与置信度。

### 17.6 Agent 内心与自动进化

- Agent 可以“想但不说”，想法和说出的内容可以不同。
- 用户可在后台查看 Agent 日记：观察、假设、考虑过的帮助、未说出口的内容、没有打扰的原因、新发现和待验证问题。
- 低风险惊喜允许暂缓公开；执行或放弃后再进入可见日记。
- Agent 日记永久保存且不可单条删除，可隐藏敏感片段。
- 日常反馈自动提炼为 Skill，无需逐条要求用户确认；Skill 在后台可见、可追溯到来源经历。
- 人格、事实记忆、提醒习惯和 Skill 支持分层重置；也可创建一个新 Agent 并保留旧 Agent 的历史回放。

### 17.7 数字生命形象

- 形象不是拟人、猫或传统宠物，而是具有猫一样好奇行为的数字生命。
- 暂定视觉原型为“记忆微光体”：半透明意识核、记忆粒子轨道、无固定轮廓和随状态变化的光脉冲。
- 成长体现在形态复杂度、行为默契、共同语言和记忆星群，而不是单一等级或体积膨胀。
- 用户可以为自己的数字生命命名；物种名和产品品牌名可独立设计。
- Agent 可以在桌面移动、贴靠窗口、以动作和气泡吸引注意，也可以在用户专注时收缩、降亮度并保持安静。

### 17.8 数据、模型与账号

- 产品不要求注册账号；Agent 是用户本地数字世界的一部分。
- 用户选择 Agent Home 文件夹，使用开放格式保存 Markdown 日记、结构化 Memory、Skill、证据和生命状态，并支持导入迁移。
- 云端能力由用户填写自己的模型 API Key；API Key 保存在 macOS Keychain。
- 首次引导让用户选择本地、云端或未来的自动路由模式。研发顺序为先云端、后本地、最后实现路由模型。
- 云端调用必须可见并保留上传记录；本地模式不上传 Context。
- 聊天正文可在用户授权后进入活动与长期社交记忆，用于记住承诺、未回复消息和关系 Context。
- 支付密码等极高风险信息在任何情况下都不允许采集；聊天等敏感来源由用户逐项授权。

### 17.9 主动服务优先级

MVP 首批主动服务为：

1. 走神后的一键任务现场提示与返回。
2. 每日活动日记和双视角语义回放。
3. 从历史 Memory 中发现与当前任务有关的内容。

社交方向的首个闭环是：发现用户答应过他人的事情、重要对话长期未回复或承诺临近到期；Agent 可以提前准备但不发送回复内容，在空闲、打开对应应用或临近截止时温和提醒。
